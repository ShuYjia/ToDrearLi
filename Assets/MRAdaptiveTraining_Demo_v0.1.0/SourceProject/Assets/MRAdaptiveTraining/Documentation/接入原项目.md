# 接入现有单人教学任务

先接一个可独立重置的任务，验证后再接其他关卡。本包不包含原项目的类名、任务状态机或 PICO SDK 假设。

## 准备信息

接入者需要找到：任务开始、任务成功/失败、明确知识或操作错误、设备交互异常、完整重置、继续教学这几个入口。如果没有现成的重置能力，应先实现并人工验证，不能用清零分数代替任务重置。

## Inspector 连接

1. 在真实任务场景中创建独立 GameObject，添加 `AdaptiveTrainingController`。不要把整个演示预制体当作真实任务控制器。
2. 在 Project 右键 `Create > MR 教学 > 任务评价规则` 创建本任务专用规则资产。
3. 将规则拖到控制器的 `Policy` 字段，设置稳定且唯一的 `Task Id`。
4. 正式接入取消 `Use Demo Storage`。只在所有明确错误事件都已接入后勾选 `Error Tracking Available`。不要为获得好看的结果提前勾选。
5. 把 `On Repeat Requested` 连接到本任务的重置入口；重置真正完成之后调用 `BeginNextAttempt()`。
6. 把 `On Continue Requested` 连接到原教学流程的继续入口。
7. 把 `On Teacher Review Requested` 连接到“暂停训练/请求教师处理”界面。没有教师界面时至少停止自动推进并给出明确提示。
8. `On Result Ready` 可连接结果面板刷新。用户确认或教学流程准备好后调用 `ApplyDecision()`，每个结果仅执行一次。

事件也可以通过 C# `AddListener` 订阅；不要同时使用 Inspector 和代码重复订阅同一个操作。

`TeacherDashboard` 可添加到电脑端教师场景，连接同一控制器并勾选 `Standalone Window`。演示场景已经连接，无需手动拖拽。此面板是 IMGUI，不能直接当作 PICO 射线交互面板。

## 必须调用的接口

| 原任务发生的事情 | 调用 | 约束 |
|---|---|---|
| 开始一轮完整训练 | `controller.BeginTraining(studentId)` | 返回 bool；失败时查看 LastError；首个尝试会同时开始 |
| 明确错误发生一次 | `controller.ReportError("wrong_part")` | 用稳定代码；设备追踪错误不要调用此接口 |
| 追踪、抓取或数据异常 | `controller.ReportInteractionIssue("tracking_lost")` | 该次尝试标为待核实，不将异常计为能力错误 |
| 本次尝试结束 | `controller.CompleteAttempt(allRequiredStepsCompleted)` | 布尔值来自真实教学步骤检查，不能为了过关写死 true |
| 结果显示后执行安排 | `controller.ApplyDecision()` | 保存成功后才触发重练、继续或教师处理事件 |
| 重练事件后，重置已完成 | `controller.BeginNextAttempt()` | 只能在收到重练许可后调用；异步重置要等待完成 |
| 明确中止训练 | `controller.AbortTraining("原因")` | 活跃尝试记为中断，停止会话；不会自动进入下一关 |
| 保存失败后重试 | `controller.RetrySave()` | 成功后再调用 ApplyDecision |

不要在每次重练时调用 `BeginTraining()`。该接口会创建新会话；重练应保留同一会话并调用 `BeginNextAttempt()`，否则会丢失连续稳定性与补练上限的语义。

## 适配示意

以下只是接线示意，`OriginalTask` 不是包内类型，需要替换为原项目真实类型与方法。不要直接把占位代码当作已完成接入。

```csharp
// 场景初始化时订阅一次；在销毁时 RemoveListener。
training.onRepeatRequested.AddListener(HandleRepeat);
training.onContinueRequested.AddListener(originalTask.ContinueTeaching);
training.onTeacherReviewRequested.AddListener(originalTask.ShowTeacherReview);

void StartLesson(string studentId)
{
    // 原任务应已处于干净初始状态。BeginTraining 成功后再允许学生交互。
    if (training.BeginTraining(studentId)) originalTask.EnableInteraction();
}

void HandleRepeat()
{
    originalTask.ResetAllTaskState(); // 若异步：等待完成后才执行下一句。
    training.BeginNextAttempt();
}

void OnRealTaskFinished()
{
    originalTask.DisableInteraction();
    training.CompleteAttempt(originalTask.AllRequiredStepsCompleted);
    // 显示结果；确认后调用 training.ApplyDecision()。
}
```

本模块不会查找并操纵场景里的抓取物、动画或碰撞体。真正的重置由原任务负责。成功导入且 Console 无编译错误，只证明代码能编译，不能证明接线正确。

## 规则参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| policyVersion | demo-v1 | 变更规则后更新版本；每次记录保存完整快照 |
| baselineOptionalRepeats | 2 | 首次必要操作之外的基准重复次数，所以默认共 3 次 |
| minimumOptionalRepeats | 0 | 课程不允许省略的最低重复次数 |
| maximumAdditionalRepeats | 2 | 需要加强时，在已有安排后最多增加 2 次 |
| maximumTotalAttempts | 5 | 单轮总尝试硬上限，含未完成尝试；达到上限仍未完成则交教师 |
| cleanAttemptsForMastery | 2 | 当前会话中连续可靠、必要步骤完成且零明确错误的次数 |
| errorsForNeedsPractice | 2 | 单次明确错误达到此阈值则需要加强 |

规则在 BeginTraining 时复制，运行中改 Inspector 不会悄悄改变当前会话。新规则从下一轮训练生效。每项任务单独配置并由教师确认，本包不提供通用的“科学阈值”。

数据不可靠或错误采集不完整时：状态为待核实，保持已有训练量，不依据异常缩短或增加可选训练；必要步骤不完整时仍必须重做，达到上限交教师。

## 接入验收

1. 正确、一般、错误较多三条路线分别出现 2、3、5 次尝试（默认规则）。
2. “执行安排”确实改变真实任务流程；不只是界面文字不同。
3. 未完成必要步骤时绝不触发 `On Continue Requested`。
4. 每次重练任务状态干净；错误事件没有重复订阅。
5. 日志学生标识、任务标识、尝试次数与实际一致，重启后可读取已提交记录。
6. 异常追踪、缺少错误采集时显示待核实；补练上限生效。
7. 头显操作、中文字体、暂停恢复、IL2CPP/Android 构建、本地存储均在目标工程真机核实。

## 多人版本的边界

不要把单人控制器直接连接到共享关卡“重置/下一步”。否则一个人的评价可能重置其他人的任务。

后续至少要明确每名学生独立记录、服务器/主机权威、共同必做步骤、个人补练发生的时机，以及共享任务怎样处理不同建议。这些取决于原项目多人架构，本包没有伪装成已支持多人。

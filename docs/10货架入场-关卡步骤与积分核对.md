### 8.1 框架如何把步骤“推”起来（前置机制，三条）

**① 双侧同名节点同时激活 —— `NodePanelBase.SetSceneNodeActive`**（`BusinessLogic/NodeScripts/NodePanelBase.cs:57-96`）

```csharp
foreach (GameObject sceneRoot in SceneManager.GetActiveScene().GetRootGameObjects())
{
    if (sceneRoot.name != "有交互物体" && sceneRoot.name != "无交互物体") continue;   // 两个根都遍历
    foreach (Transform courseRoot in sceneRoot.transform) { /* 匹配课程名 */
        foreach (Transform nodeRoot in courseRoot)
            nodeRoot.gameObject.SetActive(nodeRoot.name == nodeName);                  // 同名置 true，同级其余置 false
    }
}
```

这解释了 §7.2 里 `10货架入场` 两侧序列化都是 `m_IsActive: 0` 却仍然可用：M10 面板一打开，**两侧的 `10货架入场` 会被同时激活**，其余 10 个模块节点被关掉。因此：

- 交互侧 `TexCore_10Steps`（货架 + 门控）→ 激活；
- 无交互侧 `changjing-4`（**AGV1** + 50 个 `huojia` 目标点 + 旧视频锚点）→ **同样被激活**，`OnTriggerEnter` 才可能发生。

**③ 状态分发与触发 —— `TexCore_StepObj`**（`ObjState/TexCore_StepObj.cs`）

| 收到的广播 | 判定 | 调用 |
| --- | --- | --- |
| `设置物体状态(n,t,s)` 且与某 stepObj 的 `(i,j,stepIndex)` **相等** | 正在做该题 | `SetState(等待触发)` → **`UnderWay()`** |

**完整流程（含玩家动作）**：

| # | 触发源 | 行为 |
| --- | --- | --- |
| 1 | 载入 02 面板 → `(9,2,0)` | 货架 `UnderWay()`：`stepActive=true`；把 `targetIndex…49` 号目标点 `SetActive(true)`；自身激活；`ObjectManipulator.enabled=true`（`AllowedManipulations = Move`，**只允许平移、不可旋转缩放**）；调 `TexCore_10BackpackController.Present(this)` |
| 2 | 背包 | 面板 `10货架入场背包面板`（运行时由 `06货架安装背包面板` 模板实例化，标题「10货架入场 / 点击货架，从背包取出待搬运货架。」）被打开；因 `rackSummoned=false`，立刻调 `WithholdUntilSummoned()` 把**货架本体 `SetActive(false)` 藏起来** |
| 3 | **玩家：点背包「货架」按钮** | `SummonRack()` → `ReleaseFromBackpack()`：货架 `SetActive(true)` + `ResetRackToSpawn()`（回到 `10_货架生成点`、速度清零、复原缩放）+ `TexCore_BackpackPhysics.Stabilize` + 恢复抓取；面板关闭，提示「已从背包取出货架，请将货架接驳到机器人。」（重复点击提示「货架已经取出，请将它接驳到机器人。」） |
| 4 | **玩家：把货架拖进 AGV1** | `OnTriggerEnter` → `!attachedToRobot && IsRobot(other)`（父链命中 `robot` 或 tag `jiqiren`）→ `AttachToRobot()`：`SetParent(AGV1, worldPositionStays:true)`、`attachedToRobot=true`、清速度 → 提示「货架已接驳机器人，请将机器人移动到高亮货架点。」 |
| 5 | **玩家：拖动 AGV1，把货架送进当前目标点触发盒** | `OnTriggerEnter` → `IsCurrentTarget()`（目标必须是 `activeInHierarchy`，且 `other` 是目标本身／子物体／父物体） |
| 6 | 结算 `CompleteCurrentTarget()` | 再过一道 **`Vector3.Distance(货架, 目标) ≤ 0.24`**；未过则**静默返回**；过了则：货架 `SetParent(null)` 并**吸附到目标位姿** → 目标点 `SetActive(false)` → `targetIndex++` |
| 6a | 若 `targetIndex < 50` | `ResetRackToSpawn()`（**货架脱离 AGV、瞬移回 `10_货架生成点`**）+ 恢复抓取 → 提示「已完成 n/50 个货架点，请继续搬运下一货架。」→ **回到第 3 步** |
| 6b | 若 `targetIndex == 50` | `userCompleted = true`、`completed = true`、`stepActive = false`、关抓取、关背包 → `TexCore_BusinessManager.OnClick(货架)` |
| 7 | 上报落点 | `TexCore_PlaneManager.activePlane.OnClick(货架)` → `Panel_Operate.OnClick`：`obj.name == tasks[0]` → `steps.Add`、`stepIndex=1` → `CalculateScore()` → **`haveScore = 10`** → `Submit()` → 显示 `下一步` |
| 8 | **玩家：点 `下一步`** | `NextTopic()` → 载入 `03完成整个模块` |

> **关键结论：这是「一个货架复用 50 次」的循环**（类注释原话：*A single movable rack is reused for each target point*）。
> 每完成 1 个目标点，货架都会被强制送回生成点并脱离 AGV —— 因此上述第 3～6 步要**重复 50 次**，
> 即玩家需 **取货架 50 次 + 重新接驳 AGV 50 次**，而不是「接驳一次、机器人自己跑完 50 点」。
> 提示词里的「依次到达高亮货架点」与实际实现（每次重置）存在体验落差，见 §8.6。

### 8.7 步骤细节层面新发现的 5 条（已在 §7.6 的“遗留”之外）

| 级别 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- |
| 中 | **提示词承诺的「高亮货架点」并未实现** | `hintTexts[0]` 写「高亮货架点」，但 `SetTargetPointsActive()` 只做 `SetActive(true)`，全类无描边／材质／颜色切换；目标点要等轮到才激活，玩家看不到「下一个是哪个」 | 在 `UnderWay()`/`CompleteCurrentTarget()` 里给 `targetPoints[targetIndex]` 加 outline 或换材质 |
| 中 | **50 次取货＋接驳的人力成本** | 每次结算都 `ResetRackToSpawn()`，货架脱离 AGV 回到 `10_货架生成点` | 若目标是「接驳一次跑完」，应保留货架→AGV 父子关系，仅在最后一个点解挂；否则把 50 点降到个位数 |
| 中 | **容差只在结算里判，失败无提示** | `OnTriggerEnter` → `CompleteCurrentTarget()` 先过 `Distance > targetTolerance(0.24)` 才结算，未过直接 `return` | 未达成时给一次提示（如「再靠近货架点一点」），或把容差判断改成持续检测 |

# 06 货架安装构建经验

> 核对日期：2026-07-29  
> 当前实现：`Assets/A_MRNet/Sence/03SingleplayerScene.unity`  
> 控制脚本：`Assets/A_MRNet/Scripts/TexCore_RackAssemblyController.cs`

## 1. 文档用途

本文记录当前 BPF 框架中“06 货架安装”的实际构建方法和已验证约束，供后续维护06以及构建07播种墙等四态组装关卡时复用。

旧 `WHY_HJ` 只作为模型、位置、步骤、提示和音频来源。当前实现不复用旧场景中的 Mirror、`SycObj`、`Tank.prefab`、`LoadSceneObj` 或多人同步状态机。

## 2. 当前框架结构

06由三部分组成：

| 部分 | 当前对象或文件 | 职责 |
| --- | --- | --- |
| 大关与题目数据 | `Assets/Resources/BusinessPrefabs/.../06货架安装.prefab` 及其 `01货架安装操作.prefab` | 题目顺序、分值、提示、音频和框架数据记录 |
| 场景状态 | `无交互物体/.../06货架安装/WHY_HJ` | 保存取件模板、蓝色目标、绿色预览、完成实物和最终货架 |
| 交互步骤树 | `有交互物体/.../06货架安装/01货架安装操作` | 21个 `TexCore_RackAssemblyStep`，按 `stepIndex` 0至20接入 `TexCore_StepObj` |

核心调用关系：

```text
TexCore_StepObj
  -> TexCore_RackAssemblyStep.UnderWay()
  -> TexCore_RackAssemblyController.ActivateStep(stepIndex)
  -> 背包生成当前物品/工具
  -> TexCore_RackAssemblyInteractable 监听释放
  -> 目标判定成功
  -> TexCore_BusinessManager.OnClick(stepReporter)
  -> 框架切换下一步骤并记录状态
```

## 3. 四态对象规则

每一种可安装物体必须建立同索引映射：

```text
HuoJia_cube   可从背包生成的移动模板
HuoJia_blue   未完成时显示的安装位置
HuoJia_green  物体进入有效范围后的绿色预览
HuoJia_shi    安装成功后的最终实物
```

关键约束：

- `blueTargets[i]`、`greenTargets[i]`、`resultObjects[i]` 必须表示同一个安装位置。
- 进入容差范围：隐藏蓝色目标，显示绿色预览。
- 离开容差范围：恢复蓝色目标，隐藏绿色预览。
- 只有在有效范围内释放才完成；范围外释放不吸附、不完成。
- 成功后隐藏蓝色和绿色对象，显示最终实物，并销毁本次背包生成物。
- 回退或直接切换步骤时，通过已完成步骤数重建所有四态，不能依赖上一帧遗留状态。

## 5. 背包配置

06使用独立章节 `06货架安装背包面板`，与通用背包内容互斥：

- 进入 `PlacePart` 或 `UseTool` 步骤时显示06章节。
- 退出06、完成步骤或切换到通用章节时隐藏06章节。
- 背包按钮只负责调用控制器的明确取件方法，例如 `SpawnBottomBase()`、`SpawnUpright()`、`SpawnGlue()`。
- 控制器必须检查当前步骤和 `partKey`，错误物品不能生成。
- 同类重复件共用一个隐藏模板，每次点击生成独立运行时实例。

运行时生成物统一补齐：

- `ObjectManipulator`，仅允许移动；
- `Rigidbody`，关闭重力；
- `TexCore_RackAssemblyInteractable`，监听释放并更新预览与指引；
- 移除模板中遗留的 `TexCore_InteracterBase` 身份，避免一个生成物同时进入两套步骤生命周期。

## 6. UI、音频与视觉指引

### 统一提示 UI

提示文案放在当前 BPF 题目数据中，由框架显示，不启用旧 `ZhiYin` Canvas。文案应同时说明：

- 从背包取什么；
- 数量；
- 安装到哪里或使用什么工具；
- 当前完成进度。

### 音频

- 复用 `WHY_HJ/ZhiYin` 对应步骤的音频资源。
- 进入步骤时播放；无音频的步骤保持静音。
- 切换、回退或退出步骤时先停止上一段音频。
- 同一旧提示拆成多个精细交互步骤时可以复用同一段音频，但不能同时叠播。

### 位置指引

运行时生成物使用与01服务器网络搭建一致的视觉语言：

- 当前移动物或工具：黄色脉冲圈；
- 最近的未完成目标：青色脉冲圈；
- 两者之间：黄到青的方向线和青色箭头；
- 物体移动时每帧更新；
- 放置成功、销毁、步骤切换或控制器失活时立即隐藏并释放运行时材质。

不要直接给生成物挂 `TexCore_OrderedPlacementStep`。该组件属于固定场景对象的序列化步骤生命周期；06的物品是背包动态生成且目标会在一组未完成位置中变化，因此只复用其视觉算法。

## 7. 前进、回退和随时切换

每次激活步骤都执行以下顺序：

1. 清理上一步生成物和目标预览。
2. 根据目标 `stepIndex` 恢复完整货架初始姿态。
3. 依次应用目标步骤之前所有步骤的完成态。
4. 显示当前步骤未完成的蓝色目标或工具目标。
5. 清空当前步骤完成计数。
6. 显示对应背包章节并等待操作。

因此从第20步回到第3步时，场景应只保留第0至2步的完成实物；第3步及之后恢复未完成状态。最终货架使用启动时记录的原始坐标，不能把临时调试位置保存为新基准。

## 8. 数据记录边界

- 步骤完成必须由 `TexCore_BusinessManager.OnClick(stepReporter)` 回到现有框架。
- `TexCore_RackAssemblyController` 只管理当前组装状态，不另建一套题目归属、计分或保存系统。
- `TexCore_RackAssemblyStep` 必须仍在 `TexCore_StepObj.interacterObjs` 的正确节点、题目和连续步骤索引中。
- 题目名称、父节点 `childData` 和 Topic Prefab 文件名必须完全一致。
- `Assets/StreamingAssets/Config.xml` 是生成结果，不作为手工配置源。

## 9. 已验证结果

当前 Unity Play Mode 已验证：

- 21个步骤定义和21个步骤组件存在；
- 空引用和 Missing Script 为0；
- 底座生成后出现黄圈、青圈、方向线和箭头；
- 指引随移动物更新；
- 胶水等工具步骤同样显示指引；
- 最终货架移动步骤显示指引；
- 靠近时蓝关绿开，远离后蓝开绿关；
- 步骤切换和退出后指引立即隐藏；
- 本次控制脚本编译错误为0。

项目仍存在与本功能无关的历史 XR/OpenXR、序列化深度和调试级 `LogError`，不能把这些旧控制台信息误判为06脚本错误。
